# V2 UI — Completion Audit & Cutover Checklist

> **Purpose:** track which V1 pages/routes have a real V2 equivalent, so we know when
> `/v2` can replace V1 wholesale. This is the running scoreboard — update it as pages land.
>
> **Sources of truth for this audit:**
> - V1 surface to match → [`V1_UI_Map.md`](./V1_UI_Map.md)
> - V2 architecture / what each built section does → [`V2_UI_Structure.md`](./V2_UI_Structure.md)
> - Route registries (the machine-readable "is it built?" signal) → [`ui/src/routes/*.routes.ts`](../ui/src/routes/)
>
> **How "built" is determined:** a registry entry with an `element` renders a real page; without
> one it renders the shared [`Placeholder`](../ui/src/pages/_shared/Placeholder.tsx). Nested sections
> (billing, email, marketplace…) route internally — a few of those sub-routes render a themed
> [`ComingSoon`](../ui/src/pages/admin/billing/ComingSoon.tsx) stub and are marked 🟡 below.

**Legend:** ✅ Done · 🟡 Partial (shell built, some sub-routes/features stubbed) · ⬜ Not started (Placeholder) · ➖ intentionally dropped/merged

## 6. Remaining work to retire V1 (the punch list)

**Hard blockers — V1 has these, V2 must before cutover:**
- [x] Server: **Files** manager (incl. file edit/view) ✅ — browser + CodeMirror editor, SFTP/SSH drawer, advanced search. Scoped out for now: chmod / compress / decompress.
- [ ] Server: Databases, Backups, Schedules, Subusers, Network, Startup, Settings
- [ ] Server: Activity, Billing, Extensions, AI, Custom Domains
- [x] Auth: Register, Forgot/Reset password (email + recovery-code) ✅ · [ ] Discord link/register
- [x] Auth: surface `users.recovery_code` ✅ — code is now **hashed** (was reversible `Crypt`), shown once on the register screen (copy/download), and regenerated via a password-gated modal at `/v2/account/settings` (Recovery code card). Backend: `verify()` uses `Hash::check`; new `RecoveryCodeController` (`GET`/`POST`/`acknowledge` under `/api/client/account/recovery-code`); `recovery_code_seen` now driven for the "not saved" nudge. **Note:** pre-existing users' legacy encrypted codes no longer validate — they must regenerate from settings.
- [ ] Account: **API keys + SSH keys** (V1 `credentials`)
- [ ] Account: Orders + invoice history (`billing/orders`, `billing/order/:id`)
- [ ] Admin: Overview dashboard
- [ ] Admin: finish Billing stubs (orders, invoices, coupons, exceptions, settings, invoice-settings)
- [ ] Admin: Nests + Eggs editor
- [ ] Admin: Auth (JGuard), Custom Domains, AI, Webhooks, Alerts, Databases, API Docs

**Non-blocking / verify before flipping the switch:**
- [ ] Per-user locale picker (panel default already works)
- [ ] Confirm every 🟡/➖ merge (security→settings, nodes+servers→infrastructure) preserves all V1 capabilities
- [ ] Sweep for V1 routes not represented in any V2 registry (e.g. `billing/order/:id`)
