# V2 UI — Completion Audit & Cutover Checklist

> **Purpose:** track which V1 pages/routes have a real V2 equivalent, so we know when
> V2 could replace V1 wholesale. **Cutover executed 2026-07-16** — V2 serves at the site
> root and V1 is archived; see [`v1-cutover/`](./v1-cutover/) for the executed record.
>
> **Sources of truth for this audit:**
> - V1 surface to match → [`V1_UI_Map.md`](./V1_UI_Map.md)
> - V2 architecture / what each built section does → [`V2_UI_Structure.md`](./V2_UI_Structure.md)
> - Route registries (the machine-readable "is it built?" signal) → [`frontend/src/routes/*.routes.ts`](../frontend/src/routes/)
>
> **How "built" is determined:** a registry entry with an `element` renders a real page. Every
> entry now has one — `element` is required by the registry type, and the old `Placeholder`
> fallback and `ComingSoon` stub have both been deleted — so the 🟡 rows below are historical.
>
> ⚠️ **Audited 2026-07-15 — this scoreboard was incomplete.** It tracks *pages ported*, and by
> that measure it was right; but it never listed V1's **admin Links module** (since
> [ported](#links-custom-links) — the audit is what surfaced it). The deeper lesson stands: a
> page-parity scoreboard is blind to the non-page regressions the audit found — route permission
> enforcement, CI coverage, extension packages — and those are the remaining blockers. Read
> [`v1-cutover/01-audit-findings.md`](./v1-cutover/01-audit-findings.md) alongside this file.

**Legend:** ✅ Done · 🟡 Partial (shell built, some sub-routes/features stubbed) · ⬜ Not started (Placeholder) · ➖ intentionally dropped/merged
